# 资产、标签与状态审计（v3）

## 结论先行

1. **三张表**：`assets`（一台一份，字段各有唯一含义）、`tags`（一张贴纸＝一个袋）、`asset_state_changes`（状态变动审计）。
2. **不做通用事件表**。`rating` 只属于"拼完评价"、`amount` 只属于"买入/卖出"，把它们挂在同一个 `kind` 上，等于让每行带着一堆永远为空的列——这是把不同东西塞进一张表的典型症状。
3. **两套时间要分开**：业务事实（八月拼的）存 `assets.built_on`；系统事实（今天录的）存审计表的 `changed_at`。一张 event 表同时承担这两件事，才会逼出 `occurred_at` 和 `created_at` 谁是谁的混乱。

## 一、三张表

| 表 | 一行是什么 | 什么时候写 |
| --- | --- | --- |
| `assets` | 我拥有的那一台 | 买入时插入；之后改字段 |
| `tags` | 物理上的一张贴纸／一个袋 | 收纳时创建，卖出时作废 |
| `asset_state_changes` | 一次状态变动 | 每次状态改就追加一行 |

资产可以没有 tag（待拼、展示、收藏），但 tag 一定属于一台资产。

## 二、状态

```text
待拼 ──拼完──> 展示 <──收纳/取出──> 收纳
  │              │                 │
  └──> 收藏      └─────────────────┴──> 卖出
```

图中省略了 `pending / keep → sold` 的直连：任意非 `sold` 状态都能直接卖出；`sold` 没有出边。

| 状态 | 含义 | 潜台词 | 有 tag |
| --- | --- | --- | --- |
| `pending` 待拼 | 买了没动，堆在盒子里 | 未拼 | 通常无 |
| `keep` 收藏 | 不打算拼，留盒 | 未拼 | 通常无 |
| `displayed` 展示 | 拼完摆在外部 | **已拼** | 可能有（空袋／余件袋） |
| `stored` 收纳 | 拼完封袋收起来 | **已拼** | 通常有（也可能还没打） |
| `sold` 卖出 | 已出手，记录保留 | 看 `built_on` | 所有 tag 写 `retired_at`，不再进打印队列 |

要点：

- "已拼"不是状态，是 `displayed / stored / sold` 的**共同潜台词**；拼没拼过看 `built_on` 是否为空。
- `displayed ⇄ stored` 允许来回切，这是日常动作（拿出来摆、收回去），审计表会记下每一次。
- **任意非 `sold` 状态都可以直接卖出**：`pending / keep / displayed / stored → sold`。
- **`sold` 是终止状态**：不能从 `sold` 改回任何状态。误操作只能删资产重建（以后真需要再加专用撤销）。
- 状态迁移只有一份定义（`backend/app/states.py`），抽屉和批量按钮都读 API 返回的 `allowed_next_states`，后端也会拒绝非法迁移，不会出现“这个入口能点、那个入口不能点”。
- **不要用"有没有 tag"推断状态**：袋子拿空了、东西在架子上，tag 还在。两个概念会打架。

## 三、`assets`

| 字段 | 说明 |
| --- | --- |
| `id` | 内部主键 |
| `product_id` | → `products`；同款两台就是两行 |
| `code` | 5 位随机码（Crockford Base32，去掉 I/L/O/U），如 `K7M2Q`；由 service 分配，**不复用** |
| `state` | 五值枚举 |
| `note` | 自由备注（断件位置、改色思路） |
| `acquired_on` | 买入日期 |
| `purchase_price` | 买入价 |
| `built_on` | 拼装日期 |
| `rating` | 1–5 星 |
| `review` | 评价文字 |
| `sold_on` / `sold_price` | 卖出日期与价格 |
| `created_at` | 建档时间 |

每个字段都只有一个含义、只在一个阶段有意义，空着就空着。没有 `condition`：
"缺件/断件"写进 `note` 就够了，做品相枚举只会逼你在"这算 incomplete 还是 damaged"上纠结。

## 四、`tags`

| 字段 | 说明 |
| --- | --- |
| `asset_id` | → `assets` |
| `seq` | 1 = 第一个袋；2、3… = 后面的袋 |
| `code` | 每张独立随机码，如 `R4TB9`；与资产码无关、互不复用 |
| `title` | 印在徽标上的袋名：`本体` / `地台` / `配件包 2`（自由文本 + 预设） |
| `printed_at` | 最近一次打印时间（空 = 已生成未打印） |
| `retired_at` | 卖出时写入；作废后不再进打印队列，不能重打/加袋 |

- **不是流水号**：随机码不暴露你有多少台、什么时候入坑。5 位 32 进制约 3300 万组合，撞了就重试。
- **每张标签各自独立**：第二袋不会写成 `K7M2Q-2`，而是另一个随机码。袋子之间没有可见关系，但都能通过 `asset_id` 落到同一台资产。
- 字母表去掉 `I / L / O / U`，手输不会和 `1 / 0` 混；查询时把 `O→0、I/L→1` 归一化并忽略分隔符，输错也能命中。
- **袋名是自由文本**，预设（本体／余件／地台／配件包）只做输入辅助。枚举撑不住"配件包 1/2/3"这种开放式命名。
- 徽标样式按预设区分（本体实底、余件描边、地台虚线），纯黑白也能一眼分拣。
- 重打和加袋是两件事：
  - **重打** = 同一个袋、同一张码，只是纸没了 → 队列切到「已打印」，勾选再打，`printed_at` 往后挪。
  - **加一个袋** = 真的多了一个袋子 → 新行，`seq + 1`，新码。
- **卖出即作废**：`retired_at` 只在资产卖出时写入，这是唯一能观测到的“这批袋子不再流通”的事件。作废后标签不再进「待打印 / 已打印」队列，也不能重打或加袋；行保留，作为这个袋子的历史。要彻底清掉，删资产会级联删标签。
- 作废标签不会自动删除，也不会被重新激活：`sold` 不能退回，所以不存在“卖出后又把旧码贴回去”。
- 作废标签可以在 `GET /tags?status=retired` 里查；`status=all` 也保留它们。日常打印队列只看 `open / printed`。
- `printed_at` 由打印动作写入，不设"已贴"按钮：能观测到的只有"出纸了"，其余交给现实。
- 资产页面**不展示**标签：贴纸是标签队列的事，资产只管状态和买卖；抽屉里只有「再加一个袋」这个动作。卖出后该入口隐藏，并提示标签已作废。

## 五、`asset_state_changes`

| 字段 | 说明 |
| --- | --- |
| `asset_id` | → `assets` |
| `from_state` | 首行（建档）为空 |
| `to_state` | 新状态 |
| `changed_at` | 系统时间（写入时） |
| `note` | 可选，为什么改 |

写入规则：**改状态和写审计在同一个事务里**，否则两边会漂。审计只记状态，不记字段编辑——
"改了个错别字"不值得留痕。

## 六、为什么不要一个 event 表

上一版我设计的 `asset_events(kind, occurred_on, amount, rating, note)`，问题在这里：

```text
kind=acquired   amount=✓  rating=✗  review=✗
kind=built      amount=✗  rating=✓  review=✓
kind=sold       amount=✓  rating=✗  review=✗
kind=noted      amount=✗  rating=✗  review=✓
```

每行的字段取决于 `kind`，但表结构对所有行一视同仁。再加两件事（比如"送人时的心情"）就得再加一列，
而那一列 99% 的行都是空的。这不是"灵活"，是"没想清楚哪个字段属于哪个概念"。

资产的生命周期是**线性的**：买一次、拼一次、卖一次。既然是"一次"，它就是列，不是行。
真正会重复发生的只有**状态变动**，所以只有它需要一张流水表。

## 七、标签

### 长名字实测（1254 个产品）

| 写法 | 平均字数 | 40mm 上一行放得下 |
| --- | --- | --- |
| 全名 | 10.5（最长 31） | 3.6mm 29% / 3.2mm 33% |
| 去掉括号后缀 | 6.2 | 3.2mm 78% |
| **主体 + 副题** | 主体 5 左右 | 3.6mm 72% / 2.8mm 88%，两行覆盖 97% |

括号里装的恰恰是区分同款的信息（`钢坦克初期型破垒（镇爆配色、沙漠配色…）`），
所以不是截断，是拆行：

```text
┌─────────────────────────────┐
│ 灵皇守护者·高文              │ 3.6mm 粗体，置顶
│ KK版                        │ 2.6mm
│ SNAA                        │ 2.2mm
│ 圆桌骑士团系列               │ 2.2mm
│                             │
│ [本体] K7M2Q           ┌───┐│ 2.6mm 编号置底
└────────────────────────└───┘┘ 12mm 二维码
```

版式要点（第一版字号偏大，`灵皇守护者·高文` 被截成 `灵皇守护者·…`，所以整体收紧）：

- 主体 3.6mm 最大：40mm 宽一行放得下 9 个汉字，圆桌骑士团系列全部完整显示。
- 编号 2.6mm 置底，和类型徽标一起：编号是机器用的，人看的是名字，所以让名字先被看到。
- 厂商与系列各占一行、**左对齐**；三段（名字 / 厂商系列 / 编号）用 `justify-content: space-between` 分布，所以中间这块上下留白相等。
- 底部只留机器信息：类型徽标 + 编号 + 二维码。
- 二维码 10mm 压右下角。再大就会把中间那段的上下留白吃光——40×30 减去三块内容只剩约 6mm 可分配。

规则：

- 主体 = 第一个 `（` 之前、第一个 `&` 之前的部分。
- 副题 = `&` 之后；没有 `&` 就取第一个括号里的第一项。
- 都能人工覆盖（`label_title` / `label_sub`），否则两台不同配色会印成一样的标签。

### 规格

- 正文只写慢变量：类型徽标、编号、主体、副题、厂商·系列。不写价格、不写状态。
- 二维码只放 tag 码。40×30 主用，50×30 给地台。
- 打印走浏览器：`#print` 页面按毫米排版，`@page A4` + 4 列 × N 行，选「实际大小 100%」。版式以这个页面为准，不再维护第二套渲染器。

## 八、流程

```text
买入 → 建 assets（待拼，不贴标签）
拼完 → state=展示，填 built_on / rating / review
收纳 → state=收纳（纯逻辑，不产生标签）
出标签 → 在资产页勾选 → 生成标签 → 进「标签队列」
打印 → 队列里勾选 → 打印整版 → 打印动作写入 printed_at
卖出 → 填 sold_on / sold_price → state=卖出 → 该资产的 tags 写 retired_at
```

**先建后贴**：码在打印前必须已经在库里，标签只是投影。批量补打按码排序整版输出，走到哪贴到哪。

**逻辑和物理分开**：收纳不等于一定有标签（可以收起来了还没打），有标签也不等于在收纳（袋子空着、东西在架上）。

**卖出是终止状态**：`pending / keep / displayed / stored` 都能直接卖出；卖出后不能改回其他状态，标签永久作废。要纠正只能删资产重建。

## 九、不做

- 不做位置／容器模型（没有固定位置时它只是负担）。
- 不做说明书、水贴的册子管理。
- 不做通用事件表、不做字段级审计。
- 不做品相枚举。
- 不做卖出撤销：卖出是终止状态；以后真需要再加专用撤销，不复用状态迁移。
- 不做标签手动报废：作废只由卖出触发，避免标签状态和资产状态各说各话。
