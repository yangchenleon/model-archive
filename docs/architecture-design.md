# 架构设计（当前收束版）

## 当前目标

当前只解决一件事：建立干净的产品目录。这里的产品是可区分的发行物，而不是用户实际拥有的盒子。

不在当前范围：原始 Markdown 或网页资料归档、资产录入、愿望单、收藏分组、拼装事件、价格、图片、爬虫和管理界面。

## 当前数据表

### `products`

产品目录主数据。一个产品由厂商、来源类型、产品线、模型名称和版本/配色描述；是否因配色或版本拆成不同产品，由目录规则决定。

关键字段：

| 字段 | 含义 |
| --- | --- |
| `id` | 内部 UUID 主键，不对用户暴露。 |
| `manufacturer`、`manufacturer_code`、`origin_type`、`product_line` | 自由文本，可空。 |
| `kit_name`、`variant_name` | 产品识别信息；模型名称必填。 |
| `detail` | 自由补充说明，可空。 |
| `source` | 资料来源；新 CSV 由人工填写，旧测试数据使用“初始化测试”。 |

### `assets` 与 `asset_events`

这两张表暂时保留为后续设计空间，但**当前没有导入器、API 写入流程或用户模板**。未来资产应以 `assets.product_id -> products.id` 关联；事件应以 `asset_events.asset_id -> assets.id` 关联。

## 已删除的设计

`collection_targets` 已删除。收藏分组、愿望单、纳入/跳过规则都属于未来的独立功能，不再混入产品目录。

## 导入原则

1. 产品 CSV 是当前唯一可写入口。
2. 每行必须提供模型名称；其他产品识别字段可空。
3. 导入批次来源通过命令参数显式传入，不由系统猜测。
4. 导入器仅按完整产品识别字段匹配同一产品；身份字段变化会成为新候选，必须人工核对。
5. UUID、外键、内部兼容字段不出现在模板中。

## 下一阶段

目录确认后，先定义资产的“逐盒还是数量聚合”“资产状态变更”“存放位置”和“产品选择器”规则，再实现资产表单与导入。愿望单/收藏功能在资产稳定后单独建模。
