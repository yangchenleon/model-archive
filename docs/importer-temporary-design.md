# 临时 CSV 导入器设计

## 定位

`backend/app/scripts/import_csv.py` 是目录清点期间的临时工具，不是长期数据写入协议。它可以在管理界面完成后整体删除或替换。

工具的原则是：**宁可拒绝，也不猜测、不补全、不静默改写关联。**

## 明确链路

| 输入 | 前置条件 | 成功动作 | 不满足时 |
| --- | --- | --- |
| `catalog_items.csv` | 厂商、来源类型、模型名称、资料可信度齐全 | 新建目录，或更新完全相同目录的非身份描述字段 | 报错，不创建记录 |
| `assets.csv` | 能以完整目录身份唯一找到既有目录；状态、盒况、数量齐全 | 目录尚无资产时新建一组资产 | 报错，不创建目录、不猜测资产 |
| `collection_targets.csv` | 收藏分组、收藏决定齐全；目录存在 | 新建收藏决策 | 报错，不创建目录、不跳过行 |
| `asset_events.csv` | 目录存在且只有一组资产；日期、事件齐全 | 新建事件 | 报错，不创建资产、不用当前时间代替日期 |

目录的完整识别字段是：厂商、来源类型、产品线、比例、模型名称、版本/配色、厂商编号。空字段也是身份的一部分；因此修改这些字段会变成“无法匹配”的新目录候选，而不是自动修正旧记录。

## 已删除的兜底逻辑

1. 资产导入时自动创建目录。
2. 来源类型为空时按 `待确认` 处理。
3. 来源类型为 `待确认` 时忽略来源类型匹配现有目录。
4. 资产状态、盒况、数量为空时填入默认值。
5. 收藏分组为空时静默跳过该行。
6. 事件日期为空时由数据库写入当前时间。
7. 已有记录与 CSV 内容不同但仍静默更新。

## 仍保留，但必须确认的临时假设

| 编号 | 假设 | 风险 | 后续处理 |
| --- | --- | --- | --- |
| T-01 | 一个目录项在 CSV 临时导入阶段最多对应一组资产 | 同款多盒且状态不同无法表达 | 管理界面用逐盒资产卡片解决 |
| T-02 | CSV 用目录自然字段寻找目录，而非 UUID | 更正名称/版本会无法匹配旧项 | 通过管理界面显式编辑，或单独做核对迁移 |
| T-03 | `quantity` 可代表状态和位置相同的多盒 | 个别盒子状态变化时需要拆分 | 在资产详情页拆分数量 |
| T-04 | 厂商、产品线仍是自由文本 | 拼写差异会导致重复目录 | 后续拆分为受控字典与别名表 |

以上四项不是兜底行为，而是临时导入器的能力边界。若不接受 T-01 至 T-03，应停止使用资产/事件 CSV，仅先导入目录，等待管理界面实现。

## 导出与回导

`export_csv.py` 输出无 ID 的中文清单；随后用同一文件回导，只有内容完全一致才会视为已存在并跳过。它不应被当作批量更新工具。

```bash
docker compose exec api python -m app.scripts.export_csv /app/data/drafts/current_snapshot_friendly
docker compose exec api python -m app.scripts.import_csv /app/data/drafts/current_snapshot_friendly
```
